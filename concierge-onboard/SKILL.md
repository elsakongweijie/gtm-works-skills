# 早期一个一个带上线

来源：Rahul Vohra 讲 Superhuman 早期：不经过一对一的上手就不能用；同时不能按所有早期用户的反馈去做。入口宽到手工带教不再划算时，再改成自助。https://www.youtube.com/watch?v=0igjSRZyX-w

## When to use
- 前几十到前几百个用户，你还付得起亲手带。

## When not to use
- 带一个人的成本已经高于他会付的钱，而且入口已经很宽。那时把带教里重复的步骤做成产品，而不是继续加人。

## Required inputs
- 怎样算第一次成功：{{第一次成功}}
- 现在的注册路径：{{现在的路径}}
- 最近最吵的一类反馈：{{谁的反馈}}

## The framework
早期亲手带上线，是为了让人真的到达第一次成功，也是为了你亲眼看见哪里断。可以规定不走完这一步就不能用。听得很认真，但不按所有人的话做。你要做的是一部分人想要的东西。入口宽到手工带教会亏钱时，再把已经重复的步骤做成自助。

## Workflow
1. 把 {{第一次成功}} 写成带教结束时必须发生的一件事。
2. 用 {{现在的路径}} 判断人是否会自己走到那件事。不会：这周改为你或同伴亲手带，直到发生。
3. 每次只记三样：在哪停下、你做了什么他们才会继续、他们要的功能是否服务那件成功。
4. 看 {{谁的反馈}}。如果它把你带离那件成功，写明不排期，并说明你在听谁。
5. 写停掉手工的条件：重复步骤已经能自助，而且再带下去会亏。

## Failure patterns
- 用帮助中心代替你还没亲眼见过的第一次成功。
- 每个早期用户要的功能都排进去。
- 入口已经很宽仍按亏损的方式一个个带。

## Output format
- 带教结束必须发生的事
- 这周带谁、带几次
- 明确不排的反馈
- 改成自助的条件
