# 预期和到达价值的速度

来源：Sean Ellis。有一家公司一开始只有约 7% 的人会非常失望。他把预期说清楚，并缩短到达价值的时间，下一批调查到了约四成；那是这一家的结果，不是保证。https://www.youtube.com/watch?v=VjJ6xcv7e8s

## When to use
- 你已经知道非常失望的人不多。

## When not to use
- 你还没问过真实使用者。先用「谁会非常失望」。

## Required inputs
- 首页或广告承诺了什么：{{你承诺的}}
- 用户第一次真的感到有用是什么：{{第一次价值}}
- 现在要多久才发生：{{要多久}}

## The framework
两件事一起：预期要和你真正能给的一样，到达那个价值要快。预期过大，人会失望；路径太长，人到不了那个时刻。渠道会把这个落差放大。

## Workflow
1. 把 {{你承诺的}} 和 {{第一次价值}} 放在一起。承诺更大：把首页改到你这周真能交付的那一件。
2. 把 {{要多久}} 砍到一次短使用里能发生。列出可以后置的步骤。
3. 先改这两件，再谈投放、内容和销售加人。
4. 写下改完后要再问的同一句：如果不能再使用，你会多失望。
5. 如果非常失望的理由是他们已经投入了很多迁移成本，而不是结果，标明这不是该放大的需求。

## Failure patterns
- 分数低仍去买量。
- 承诺整家公司，第一次使用却只有一个小工具。
- 把“迁移成本很高所以离不开”当成产品好。

## Output format
- 这周改成的一句承诺
- 后置的步骤
- 第一次价值发生在第几分钟
- 再问的时间
