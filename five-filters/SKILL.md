# 五条都过，才做这个

来源：Jon McNeill（前特斯拉总裁，后任 Lyft 首席运营官，DVx Ventures）。本站依据访谈转述整理，没有原片链接，数字都是他本人说的。

## When to use
- 要开新项目或新业务，还没问过它值不值得做。

## When not to use
- 你还说不清这周要改的那一件具体的事。先把事情写具体，再跑这份。

## Required inputs
- 你想做的点子：{{点子}}
- 谁会付钱：{{买家}}
- 他们现在怎么做：{{现状}}

## The framework
Jon McNeill 说 DVx 只做五条同时成立的点子：市场够大，毛利率超过五成，有还没被解决的硬问题，对手不多，以后有退出的路。先自己找到愿意付钱的人，再把事情交给别人做。他提到经常在年经常性收入接近一百万美元时才找执行长，那是他自己的做法，不是你的指标。

## Workflow
1. 对 {{点子}} 逐条判断：市场够不够大、毛利能不能过五成、难在哪、对手多不多、以后怎么退出。每一条写「过 / 不过 / 还不知道」，并写依据。
2. 不过或不知道的，只留一条。给 {{买家}} 一个这周能做的验证，用他们现在的做法 {{现状}} 当对照。
3. 如果还没有人付钱：写明先不招谁、不建什么。
4. 五条都过，才写下一步可以加大的一件事。

## Failure patterns
- 五条里过了两条就开做。
- 用市场规模代替有人愿意付钱。
- 还没客户就先找执行长。

## Output format
- 五条各一行：过 / 不过 / 还不知道，加上依据
- 这周只验证的那一条
- 现在不能做的事
- 五条都过之后的下一步
