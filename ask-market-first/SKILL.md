# 产品会先问市场要什么

来源：Jon McNeill（前特斯拉总裁，后任 Lyft 首席运营官，DVx Ventures）。本站依据访谈转述整理，没有原片链接，数字都是他本人说的。

## When to use
- 产品会在排功能，没有人先说客户这周要什么。

## When not to use
- 你还说不清这周要改的那一件具体的事。先把事情写具体，再跑这份。

## Required inputs
- 产品是什么：{{产品}}
- 客户最近亲口要的一件事：{{市场要的}}
- 你这周本来要做的功能：{{排期}}

## The framework
Jon McNeill 说，马斯克开产品会的第一句是问负责市场的人「市场要什么」。有一次答案是第二排要一张长椅，工程和供应链当场在白板上开始。讨论产品时不放投影片，因为投影片会把问题盖住。要拿出能操作的东西。软件更新是为了让产品越用越值，不是等一个完美版本。

## Workflow
1. 核对 {{市场要的}} 是不是客户原话。如果是你猜的，先列出要去问的 5 个人。
2. 判断 {{排期}} 是不是在做这句话。不是，就写停。
3. 给 {{产品}} 定这周能被 5 个客户亲手试用的一版，不要投影片。
4. 写出这次试用要回答的一个问题。

## Failure patterns
- 用内部路线图代替客户原话。
- 用投影片代替能点的产品。
- 为了等完整版，这周不给任何人用。

## Output format
- 市场要的那一件，用一句客户的话
- 这周排期里该停的
- 这周给 5 个人用的一版
- 试用要回答的一个问题
