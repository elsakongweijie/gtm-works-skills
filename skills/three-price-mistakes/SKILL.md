# 定价的三个常见错

来源：Naomi Ionita。https://www.youtube.com/watch?v=xvQadImf568

## When to use
- 你还没让人掏钱，或套餐分不清谁该买哪档。

## When not to use
- 你这季度已经按客群测过价格，而且知道哪档在升级。那时去看实验，而不是重写原则。

## Required inputs
- 现在怎么收费：{{现在怎么收费}}
- 第一天就能完成的事：{{入门就能完成}}
- 熟练以后才需要的功能：{{以后才需要}}

## The framework
常见的三件事：太晚才收费；价格偏低，而且没有按不同的人给不同的档；定完就不再碰。不收费会让人把你当成不值钱，也让你失去“谁愿意付钱”的反馈，以后再改更痛。第一天就能感到价值的功能留在入门。要花脑筋才懂的高级能力，放进以后的专业档，不要堆在第一次使用里。

## Workflow
1. 看 {{现在怎么收费}} 是不是还在推迟学习。是的话，定一个这周就能对真实用户提出的价格，允许被拒绝。
2. 用 {{入门就能完成}} 写下入门档只承诺的一件事。
3. 把 {{以后才需要}} 移出第一屏和入门档。写明它属于哪一档、什么时候才该看见。
4. 若只有一个价，加一档给用得更多、得到更多的人。不要加第三档，除非两档已经有人买。
5. 写下 90 天后要再看一次价格的日期。定完就忘，算没做完。

## Failure patterns
- 定价页变成功能矩阵，第一次使用的人看不懂。
- 把高级功能塞进入门，只为了显得值。
- 用“等有规模再收费”继续不学。

## Output format
- 这周三件事里你中了哪几件
- 入门档的一句承诺
- 移走的功能
- 这周要问的价格问题
