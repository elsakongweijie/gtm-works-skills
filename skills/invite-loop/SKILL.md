# 一次使用，带进下一批人

来源：Varun Parmar 讲 Miro 早期：社区、模板、拆掉阻力、从试用改成可以一直用的免费层。Lenny's Podcast。

## When to use
- 产品在真实工作里本来就会出现第二个人。

## When not to use
- 使用完全是单人的，硬加邀请按钮。先回到核心动作。

## Required inputs
- 产品：{{产品}}
- 会被拉进来的人：{{被邀请的人}}
- 阻力：{{阻力}}

## The framework
早期增长来自使用本身。一个人把产品用在一件会牵涉别人的事上，别人就进来了。Miro 的工作坊会一次拉进十几到上百人。模板被复制、被搜到，又成为新的入口。每一次引入阻力的步骤都要拿数据和体验看一遍，能拆就拆。限时试用后来改成可以持续使用的免费层，增长才加快。

## Workflow
1. 写出 {{产品}} 里哪一次使用会自然遇到 {{被邀请的人}}。没有这次使用，就不要做邀请活动。
2. 对着 {{阻力}}，让被邀请的人在注册之前就能完成那件小事。
3. 设计一个别人会复制的成品（模板、清单、房间），并写它会被谁搜到。
4. 给出这周只改的一个阻力，以及你要看的数字：一次使用平均带进几个人。

## Failure patterns
- 邀请文案写得很好，但点进去先要注册和审批。
- 用积分奖励邀请，而产品里没有一起做的事。

## Output format
- 那一次使用
- 要拆掉的一步
- 可被复制的成品
- 要看的一个数字
