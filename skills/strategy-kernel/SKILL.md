# 先诊断，再做连贯的事

来源：Richard Rumelt，《Good Strategy, Bad Strategy》。https://www.youtube.com/watch?v=4uWKEG0s9Kc

## When to use
- 大家同意方向，但说不出这季度第一件事。

## When not to use
- 你还没面对过客户。诊断会变成空想。先做几次真实对话。

## Required inputs
- 你现在怎么描述问题：{{你说的问题}}
- 真正挡住你的事实：{{卡住的事实}}
- 这季度排着的事：{{这季度的事}}

## The framework
不要把使命、愿景、价值观叫做战略。那些不是前提。先找出一两件真能对付的挑战。优先的意思是第一，不是把能想到的都留下。指导方针要写明针对这个诊断你做什么、不做什么。最容易漏掉的是连贯的行动：要真的去做，而且这些动作彼此配合，都对着同一个诊断。

## Workflow
1. 如果 {{你说的问题}} 只是“想要更好的结果”，标成愿望，不是诊断。
2. 用 {{卡住的事实}} 写成一个可以动手的诊断。写不出事实，就停，先去看。
3. 写指导方针：为了对付这个诊断，你不做什么。
4. 把 {{这季度的事}} 逐条问：它是否执行这个方针。不执行的，拿掉。
5. 留下的动作必须互相配合。互相抢人的，只留一件。

## Failure patterns
- 诊断写成“我们要增长更快”。
- 指导方针和行动清单是两张各写各的纸。
- 什么都重要，所以没有第一。

## Output format
- 诊断，两句，含一个事实
- 不做什么
- 留下的连贯动作
- 拿掉的事
