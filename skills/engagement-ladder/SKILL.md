# 先定义那个核心动作

来源：Sarah Tavel（Benchmark）。https://www.youtube.com/watch?v=H9g4pzcz6Tk

## When to use
- 打开、注册、停留都很热闹，业务却没有变厚。

## When not to use
- 你还不知道谁是用户。先做必须有测试。

## Required inputs
- 产品：{{产品}}
- 核心动作：{{核心动作}}
- 舍不得离开的东西：{{舍不得}}

## The framework
第一层不是打开应用，而是一个你定义的核心动作。Snapchat 是发出一条，不是打开。第二层是越用越有积累、离开会有损失。身份、关注、历史、模板，都是这种损失。没有损失，增长只是把人搬进来再漏掉。

## Workflow
1. 判断 {{核心动作}} 是不是“打开”的伪装。是的话，换成一个对别人有后果的动作。
2. 设计 {{产品}} 的第一次使用，让这个动作在一次会话里发生。
3. 写出 {{舍不得}} 如何在这个动作之后开始积累。如果用完没有任何留下的东西，标成缺口。
4. 给一个这周能改的界面或流程，只服务这个动作。

## Failure patterns
- 用通知把人叫回来，却没有核心动作。
- 把积分和徽章当成离开损失。

## Output format
- 真正的核心动作，一句
- 第一次使用如何让它发生
- 离开时会丢掉什么
- 这周只改的一处
