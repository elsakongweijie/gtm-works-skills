# 去他们已经在问的地方回答

来源：Meltem Kuran Berkowitz 讲 Deel 早期：去人们提问的地方回答，答案会留下来。https://www.youtube.com/watch?v=C1_sM0_ds2c

## When to use
- 你的买家会在公开地方问这个问题。

## When not to use
- 问题只发生在私聊里，回答无法被下一个人看见。先换一个公开的地方。

## Required inputs
- 他们正在问的那句话：{{问题}}
- 他们问这话的地方：{{地方}}
- 你能直接给的答案：{{你能给的}}

## The framework
便宜的入口，是别人已经提出的问题。你去回答，如果对得上，就不需要先买广告。不要因为一次只有一两个人就跳过。公开的回答会留在那里，后面的人反复看到。私密对话做不到这一点。

## Workflow
1. 把 {{问题}} 写成你会去搜的原话，不要写成你们的口号。
2. 确认 {{地方}} 是公开的。不是的话，换一个搜得到的地方。
3. 用 {{你能给的}} 写一条回答：先给结论，再给步骤。产品只在末尾出现一次，而且只有当它真能完成其中一步。
4. 写这周的量：回答几条，以及怎样才算有人因此来找你。
5. 若连续两周没有人沿着回答找来，改的是问题选错了，不是文案不够推销。

## Failure patterns
- 把回答写成广告。
- 只在别人看不见的私信里帮忙，然后抱怨没有积累。
- 同时开六个社区，每个都答一条。

## Output format
- 要盯的原话
- 一条可以发出去的回答
- 这周的条数
- 什么算有人找来
