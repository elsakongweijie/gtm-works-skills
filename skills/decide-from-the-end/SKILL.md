# 从结果倒推这周做什么

来源：Jon McNeill（前特斯拉总裁，后任 Lyft 首席运营官，DVx Ventures）。本站依据访谈转述整理，没有原片链接，数字都是他本人说的。

## When to use
- 这周排期排满了，说不出哪一件不做。

## When not to use
- 你还说不清这周要改的那一件具体的事。先把事情写具体，再跑这份。

## Required inputs
- 这周想要的结果：{{结果}}
- 你现在同时在做的事：{{在做}}
- 你这周真正有的时间：{{资源}}

## The framework
Jon McNeill 的决策是四步：定义想要的结果；问要成立的话什么必须为真；写清楚要投入什么；再把影响力和投入比一比。他引用 Sheryl Sandberg：不做的清单应该比做的长，清单本身就是成本。坏消息要马上说。拖着，它只会更糟。

## Workflow
1. 把 {{结果}} 写成一句可核对的话。
2. 列出要成立必须为真的 3 条。缺的输入直接问，不要编。
3. 用 {{资源}} 看 {{在做}}：哪一件直接让结果成立，哪一件只是忙。
4. 写出做的清单（最多 2 件）和不做的清单。不做的必须更多。
5. 写一条这周该马上说的坏消息。没有就写「这周还没有」。

## Failure patterns
- 从手头的项目出发，不从结果出发。
- 每件事都留一点，等于没选。
- 坏消息等到周会再讲。

## Output format
- 这周只做的事，最多 2 件
- 不做的清单
- 要成立必须为真的 3 条
- 该马上说的坏消息
