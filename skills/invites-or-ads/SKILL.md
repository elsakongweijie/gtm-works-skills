# 没人邀请，就得买用户

来源：Nikita Bier。没有邀请，就得用别的办法获客，多半是广告。他观察到，自己做过的社交产品里，每人发出的邀请从 13 岁到 18 岁大约每年少两成；做给更年长的人，就要准备用广告买每一个用户。https://www.youtube.com/watch?v=bhnfZhJWCWY

## When to use
- 没有第二个人，产品就没有意义。

## When not to use
- 一个人就能得到完整结果。不要硬加邀请。用「一次使用，带进下一批人」或获客类方法。

## Required inputs
- 产品：{{产品}}
- 必须在场的第二个人：{{被邀请的人}}
- 一次使用平均邀请几人：{{现在的邀请}}

## The framework
用户不邀请别人，你就得另找获客办法，通常是广告。如果产品靠关系网，而你的用户已经不处在“还在加人”的阶段，买来的人也不容易再拉人。先让一次真实使用非带上一个人不可，再谈预算。

## Workflow
1. 写 {{产品}} 在没有 {{被邀请的人}} 时还剩什么。如果还剩完整价值，这不是邀请问题。
2. 看 {{现在的邀请}}。接近零：停掉“先买量再优化邀请”的顺序。
3. 设计一次使用，不邀请就做不完。写出那一步发生在第几秒。
4. 如果目标用户很难再加人，直接写明：要么换一群还在加人的人，要么接受获客主要靠广告，并算出你是否付得起。
5. 这周只改那一个邀请步骤，不同时改广告素材。

## Failure patterns
- 邀请为零仍把预算花在买量上。
- 给一个人就能用完的工具硬加分享有礼。
- 用积分代替“不做完就没结果”。

## Output format
- 没有第二个人还剩不剩价值
- 必须发生的那一步
- 这周买不买量
- 只改的一个步骤
