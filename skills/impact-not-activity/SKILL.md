# 只问影响，不问忙不忙

来源：Luc Levesque，转述他在 Meta 得到的问题：战略看过了，结果什么时候出现。https://www.youtube.com/watch?v=Xf_ZXIGCQb0

## When to use
- 团队很努力，结果数字不动。

## When not to use
- 结果本身还没选定。先用「五问：你到底怎么赢」。

## Required inputs
- 结果：{{结果}}
- 这周的事：{{活动}}

## The framework
不看有多累，不看在做什么。看结果有没有变。增长团队尤其要不断把手头的事对准一个北极星。对得上就继续，对不上就停。忙和影响有关，但忙不是影响。

## Workflow
1. 把 {{结果}} 写成周五能观察的一个变化。
2. 把 {{活动}} 逐条问：它如何改变这个数字？答不出机制的，标成停。
3. 只留一件最可能推动它的事，写出负责人。
4. 写周五的检查：数字没动时，下周不加新项目，先改这一件。

## Failure patterns
- 用“都有点关系”把三件事全留下。
- 把发布了、写完了当成影响。

## Output format
- 周五要看到的变化
- 留下的一件事
- 停下的事
- 没动时的下一条规则
