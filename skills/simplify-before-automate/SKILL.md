# 先简化，最后才自动化

来源：Jon McNeill（前特斯拉总裁，后任 Lyft 首席运营官，DVx Ventures）。本站依据访谈转述整理，没有原片链接，数字都是他本人说的。

## When to use
- 想上 CRM、自动化或招人，但注册、销售或交付的步骤还没删过。

## When not to use
- 你还说不清这周要改的那一件具体的事。先把事情写具体，再跑这份。

## Required inputs
- 你想改的流程：{{流程}}
- 现在的步骤：{{步骤}}
- 你想自动化的部分：{{想自动化}}

## The framework
Jon McNeill 转述的顺序是五步：先质疑每一个需求，删掉不必要的；再删步骤；然后用手做顺；再加快，让问题浮出来；最后才自动化。他建议把流程贴出来，只留客户真正付钱的步骤，通常只是少数。自动化一个又长又错的流程，只会把错误做得更快。

## Workflow
1. 把 {{流程}} 的 {{步骤}} 逐条列开。标出哪几步是客户愿意付钱的。
2. 质疑剩下的每一步：这个需求是谁提的？删了会怎样？
3. 给 {{想自动化}} 一个判断：现在自动化，是在加快对的步骤，还是在加快该删的步骤。
4. 写出这周用手做的一版：留给谁、删掉哪几步、做完 10 次再允许上工具。

## Failure patterns
- 步骤还没删，就先买工具。
- 把内部方便当成客户愿意付钱的步骤。
- 一加快就上自动化，问题还没看见。

## Output format
- 现在该不该自动化：该 / 不该
- 删掉的步骤
- 这周用手做的版本
- 允许上工具的信号
